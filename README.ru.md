# Бот для рейтинга Liar's Bar

[English](README.md) | [中文](README.zh-CN.md) | Русский

Бот, который играет в Liar's Deck (режим Devil) в рейтинговой очереди Liar's Bar, используя только то, что видит живой игрок за
столом. За примерно 24 часа он поднялся с рейтинга 0 до таблицы лидеров (около 3000 очков).

## Быстрый старт

Чтобы запустить бота в самой игре, а не в симуляторе, см. [INSTALL.md](INSTALL.md); собранные `liars.exe`, DLL мода и веса лежат
на странице Releases.

```
git clone https://github.com/jackkowalik/liars-bar-deck-reinforcement-learning.git
cd liars-bar-deck-reinforcement-learning/rust
cargo build --release
target/release/liars fiteval --net ../weights/devil_mlp --opp rankedfit --players 4 --games 3000
```

Эта команда запускает сеть, игравшую в рейтинге, против популяции соперников, подогнанной под логи живых игроков, и печатает
процент побед, число нажатий на спуск за игру по причинам и состав заявок. `--players 3` или `2` для столов поменьше,
`--seed N` меняет порядок раздачи.

```
python -c "import json; r=json.loads(open('data/plays_public.jsonl').readline()); print(r['table'], r['claimer_hand'], r['thrown'], r['was_bluff'])"
```

Требования: стабильный Rust для симулятора и советника. Python 3.11 с PyTorch и `maturin` (для сборки `pyliars/`) для
тренировочных скриптов в `nn/`. .NET 6 SDK, MelonLoader и Steam-версия Liar's Bar для мода в `mod/`; файл проекта берёт сборки
игры из стандартного пути Steam. Живая обвязка (советник, мод, watchdog) работает только под Windows и использует `C:\liars`
как рабочую папку; симулятор, оценочный стенд и датасет от этого не зависят.

## Компоненты

- **Движок игры и симулятор** (`rust/src/engine.rs`): Liar's Deck с режимом Devil, шестизарядный револьвер, принудительные
  вызовы, Devil's Deal, от 2 до 4 мест. Миллионы партий в час на обычном компьютере.
- **Политики** (`rust/src/nn.rs`, `nn/`): MLP, обученный PPO в self-play против лиги скриптовых соперников, и трансформер,
  читающий всю историю раунда с привязкой к местам, дистиллированный из MLP и затем дообученный PPO. Оба экспортируются в
  плоский файл весов, который код на Rust исполняет без зависимостей.
- **Мод на стороне игры** (`mod/`, MelonLoader, C#): пишет публичный журнал событий каждой партии (места, ранги, заявки,
  время раздумий, вызовы, нажатия на спуск, наша собственная рука) и выполняет выбранное советником действие через
  собственные методы ввода игры.
- **Советник** (`rust/src/watch.rs`): читает журнал, восстанавливает состояние игры, прогоняет политику, печатает своё
  рассуждение и записывает действие для мода. Каждый переключатель политики — одна переменная окружения.
- **Конвейер данных** (`nn/reveals.py`, `data/`): после сессии размечает каждый ход соперника как правду или блеф, давая
  истинные метки для всех ходов соперников (около 10 000 ходов и 4 400 вызванных заявок). Метки используются только
  офлайн, живой советник их не видит.
- **Подогнанная популяция соперников** (`research/fit_population.py`, `agents::FitHuman`): частота блефа, частота вызовов,
  размеры ходов и привычка сбрасывать руку, подогнанные под размеченные логи, с вариацией от партии к партии.
- **Оценочный стенд** (`liars fiteval`): любой вариант политики против подогнанной популяции, тысячи партий за секунды,
  одинаковое зерно для A и B. Каждое изменение проходит через него перед выходом в игру.
- **Живое измерение** (`research/scoreboard.py`): процент побед по собственным счётчикам рейтинга игры, с разбивкой по размеру
  стола и рангу соперников; партии каждого варианта считаются отдельно, размер выборки задан заранее.

## Метод

1. Обучить политику self-play в симуляторе.
2. Играть ею вживую, логировать всё, размечать ходы соперников по логам.
3. Подогнать популяцию соперников под метки и поместить её в симулятор.
4. Каждое кандидатное изменение оценивать против этой популяции с фиксированным зерном до того, как оно коснётся игры.
5. Выжившие изменения запускать вживую по одному, с заранее заданным размером выборки, правилом остановки и табло, которое
   ведёт партии каждого варианта отдельно.

## Результаты

Живой процент побед по счётчикам рейтинга игры: 47-50% за 130 рейтинговых партий на столах по 2, 3 и 4 места. Случайная
игра при наблюдаемом составе столов даёт 31%. Против подогнанной популяции на стенде та же политика выигрывает 48% (4 места),
51% (3) и 67% (1 на 1).

Откуда берутся смерти бота, 240 смертей по логам:

| причина | смертей |
|---|---|
| блеф при наличии подходящей карты, вызван (в теории избежим) | 74 |
| частичный блеф (настоящие и ложные карты вместе), вызван | 60 |
| добровольный ошибочный вызов | 44 |
| принудительный вызов на правдивый сброс руки (1 на 1) | 31 |
| блеф без подходящей карты, вызван | 20 |

Другие измерения по логам:

- Люди вызывают около 22% заявок независимо от времени раздумий заявителя и вызывают правдивые ходы бота (37%) чаще, чем его
  блефы (24%).
- Ранг соперника не влияет на то, как часто вызывают блефы бота.
- Подбор игроков не зависит от рейтинга: состав рангов соперников одинаков на всём диапазоне, поэтому при фиксированной выплате
  рост рейтинга линеен по числу сыгранных партий.
- Собственные вызовы бота верны в 37% случаев: вызовы на первую заявку раунда — 62%, на заявки с третьей по пятую — 17-28%,
  принудительные вызовы — 0%.

## Смежные работы

- Проект Stanford CS224R *Bluff and Learn*: агенты CFR и NFSP для Liar's Bar; табличный CFR работает в упрощённых версиях,
  NFSP с плотной награждой по раундам лучше обобщается в полном масштабе.
- *Outbidding and Outbluffing Elite Humans* (arXiv 2511.03724, 2025): Solly, self-play агент R-NaD для сокращённого Liar's
  Poker на уровне лучших игроков-людей. Он блефует гораздо чаще людей, что согласуется с тем, что частый блеф верен, когда его
  нельзя эксплуатировать, и с нашим наблюдением: проблема не в частоте блефа, а в том, против кого он направлен.
- *Social Behaviour and Strategic Adaptation of LLMs in Multiplayer Sequential Games* (NeurIPS 2025): промпт-вариант Liar's
  Bar для изучения LLM-агентов.
- Neller и Lanctot, *An Introduction to Counterfactual Regret Minimization*; Neller и Hnath о Dudo с абстракцией несовершенной
  памяти: классическое рассмотрение игр с блефом и причина, по которой точный CFR не масштабируется на эту игру.

## Рамки и поведение

Бот действует только на публичной информации: заявки, количества, тайминги и исходы, видимые любому игроку, плюс собственная
рука. Клиент игры получает от сервера руки всех игроков; эта утечка использовалась для разметки логов постфактум и была
намеренно исключена из живого советника; размеченные руки опубликованы в `data/`, код, который их читал, — нет. Бот играл в
рейтинге против людей, не знавших, что играют против машины, что почти наверняка запрещено правилами игры.

## Датасет и веса

`data/plays_public.jsonl` содержит 15 314 заявок из 522 партий, каждая размечена как правда или блеф, с скрытой рукой каждого
места в момент заявки, рукой заявителя и фактически выложенными картами (5 616 неразмеченных заявок из 194 более ранних
партий лежат в `data/plays_unlabelled.jsonl`). `data/calls_public.jsonl` содержит 4 439 вызванных заявок с вскрытыми картами и
теми же скрытыми руками. Имена игроков заменены псевдонимами, согласованными между файлами; см. `data/SCHEMA.md`. В `weights/`
лежат сети, которые исполняет код на Rust: `devil_mlp` (та, что играла в рейтинге), `devil_tnet_r1v1` (трансформер) и
`basic_ppo2` (столы без режима Devil).

## Структура

```
rust/        движок, симулятор, политики, советник, стенд
pyliars/     Python-обёртка движка для тренировочных скриптов
nn/          обучение (PPO, дистилляция), подгонка популяции
weights/     экспортированные сети
mod/         мод MelonLoader: журнал событий, автомат очереди, выполнение действий
tools/       watchdog, запуск советника, перезапуск в простое
research/    подгонка популяции, табло, оценка вызовов, цена блефа, экспорт датасета
data/        опубликованный датасет и его описание
```
